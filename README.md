# YouTube Proxy TV Trial 0.4.0-test.1

Экспериментальный `app`-модуль для TizenBrew 2.0.5. Пакет пока не опубликован
и не установлен. Он предназначен для гостевого испытания YouTube на Samsung
Tizen 5.0. Работа реального видео на телевизоре не подтверждена.

## Файлы

- `package.json`, `bootstrap.html`, `dist/service.js` — файлы, которые
  TizenBrew загружает через jsDelivr.
- `src/service.js`, `src/browser-router.js`, `build.js` — исходники и сборка.
- `LICENSE` — GPL-3.0-only.

Сборка воспроизводится командой `node build.js`; сторонних NPM-зависимостей
нет. В этих файлах нет адреса, логина или пароля внешнего прокси, ключей Google
или личных данных. Не добавляйте их в репозиторий.

## Поведение

После запуска форма на `127.0.0.1:8114` принимает тип HTTP CONNECT/SOCKS5,
адрес, порт, логин и скрытый пароль, переключатель и проверку подключения.
Модуль не сохраняет эти значения в файл, `localStorage` или журнал; пароль
остаётся в памяти Node-сервиса до отключения/остановки и очищается из поля
формы после отправки. После перезапуска сервиса нужен ручной ввод.

Страница YouTube TV открывается через `127.0.0.1:8113`. Node-сервис разрешает
только домены YouTube и связанные статические/видео ресурсы; для них он
открывает туннель через настроенный прокси, затем проверяет TLS-сертификат
исходного домена. При отсутствии прокси запрос возвращает `503`, при ошибке
туннеля/TLS — `502`; прямого резервного соединения в сервисе нет. Браузерный
перехват направляет `fetch`, XHR, `src` и `poster` через локальный relay;
неизвестный внешний адрес блокируется. CSP HTML также ограничивает сетевые
ресурсы локальным origin. `Range` и ответы `206` передаются потоком.

Экран настроек показывает число запросов и байтов `googlevideo`, `Range`,
ответов `206`, ошибок и заблокированных запросов. Эти счётчики помогают
проверить маршрут видео, но не доказывают отсутствие всех прямых соединений
браузера или native AVPlay. Для такого вывода нужен тест на телевизоре с
наблюдением внешнего прокси и отрицательной проверкой после его отключения.

## Ограничения

- Origin страницы — `localhost`; в [TizenTube #555](https://github.com/reisxd/TizenTube/issues/555)
  автор связал такой origin с возможной ошибкой BotGuard/PO Token и остановкой
  воспроизведения примерно через минуту. Первое испытание должно длиться
  не менее 10 минут.
- Вход в Google-аккаунт не проверен и для теста не нужен. Ответы `Set-Cookie`
  удаляются, исходящие `Cookie` и `Authorization` не передаются.
- HTTP CONNECT Basic и SOCKS5 username/password не шифруют реквизиты на
  участке до прокси. TLS между телевизором и YouTube через туннель остаётся
  проверяемым.
- Совместимость подтверждена статическим анализом TizenBrew 2.0.5 и
  автономными тестами, включая эмуляцию отсутствующих в Node 4 API.
  Исполнение в реальном Tizen 5.0 ещё не проверено.

Для будущей установки через штатный TizenBrew нужен отдельный публичный
GitHub-репозиторий. В поле **Add GitHub** вводится
`owner/repo@<полный-40-символьный-SHA>`; TizenBrew добавляет `gh/` сам.
Публикация и установка требуют отдельного разрешения.
