# Samsung YouTube Proxy TV Trial 0.4.2-test.1

Локальная диагностическая сборка для TizenBrew 2.0.5 и Samsung Tizen 5.0.
Версия **не опубликована и не установлена**. На телевизоре остаётся
`0.4.1-test.1`. В этом пакете нет реквизитов настоящего прокси или Google.

## Назначение

Сборка исправляет сетевую проверку из 0.4.1. Начальный экран и управление
пультом сохранены. Форма показывает этап TCP, авторизации/CONNECT, TLS или
HTTPS, время проверки и кнопку отмены. HTTP Basic отправляет авторизацию
одновременно с CONNECT, поэтому эти два шага показаны совместно.

Проверка делает только один `HEAD` к
`https://www.youtube.com/generate_204` через введённый прокси и принимает
только ответ HTTP 2xx. Она не проверяет видеопоток и не открывает YouTube TV.
Кнопка «Открыть YouTube TV» сохранена, но для первого испытания 0.4.2 её
использовать не следует.

## Ограничения времени и отмена

- На каждый этап отводится до 9 секунд, на всю проверку до 40 секунд.
  Страница ожидает 45 секунд, затем прекращает ожидание и отправляет отмену.
- При закрытии страницы, Back или нажатии «Отменить проверку» активные
  TCP/TLS-сокеты и HTTPS-запрос закрываются. Поздние ответы не отправляются
  в закрытый HTTP-ответ. Параллельная проверка возвращает
  `CHECK_ALREADY_RUNNING`.
- `/api/test/status` сообщает только название этапа и время. `/health`
  доступен во время проверки. Успешные и неуспешные проверки считают
  отдельно от запросов реле и `googlevideo`.
- После ошибки можно повторить проверку без перезапуска TizenBrew.
  Автоматических повторных соединений с прокси нет.

## Безопасность

Тестовый сервис слушает только `127.0.0.1`; изменение настроек, получение
статуса и отмена защищены токеном страницы. Реквизиты не пишутся в файлы
или журналы; пароль очищается из HTML-поля после применения и остаётся
только в памяти сервиса до его остановки. Системная клавиатура Samsung
на телевизоре пока не исследовалась на собственное хранение введённого.

TLS-сертификат YouTube проверяется. Прямого резервного подключения при
ошибке прокси нет. HTTP CONNECT Basic и SOCKS5 с паролем не шифруют
реквизиты между телевизором и внешним прокси.

## Сборка и проверка

`node build.js` создаёт `bootstrap.html` и самодостаточный
`dist/service.js`. Для установки через TizenBrew нужны эти два файла и
`package.json`; остальные файлы служат исходниками и документацией.
Сторонних NPM-зависимостей в модуле нет. Лицензия `GPL-3.0-only`.

Тесты запускаются из этой папки файлами `tests/*.test.js`. Они используют
синтетические реквизиты и локальные сетевые серверы. Проверены успешное
соединение, ошибки адреса и порта, отказ авторизации, медленный прокси,
отсутствие ответа после CONNECT, обрыв и недоверенный сертификат TLS,
таймаут HTTPS, закрытие страницы, ручная отмена, параллельный запрос и
десять последовательных ошибок. После каждого сетевого сценария проверены
`/health` и закрытие тестовых сокетов; после ошибок повторная проверка
проходила без перезапуска сервиса.

Новый исполняемый код написан в синтаксисе ES5 и использует API, уже
применявшиеся в 0.4.1. Локальные проверки имитируют запуск в VM TizenBrew;
они **не подтверждают** стабильность на реальном Tizen 5.0. Node.js на
телевизоре не был измерен напрямую.

## Безопасное первое испытание после отдельного разрешения

1. Опубликовать отдельный коммит, зафиксировать полный SHA и сверить файлы
   с CDN. Установку согласовать отдельно.
2. Удалить запись 0.4.1, полностью остановить её сервис и перезапустить
   TizenBrew. Добавить 0.4.2 по фиксированному SHA. Не менять прошивку.
3. Сначала без реальных реквизитов проверить начальный экран, `/health`,
   стрелки, OK, Back, форму и кнопку отмены на синтетическом недоступном
   адресе. При ошибке или зависании остановиться.
4. Только после успешного безопасного испытания отдельно согласовать
   повторный ввод настоящего прокси на телевизоре. Не передавать пароль
   в чат и не делать фото заполненной формы.

Это диагностический прототип. Публикация и установка в рамках этапа 11
не выполняются.
